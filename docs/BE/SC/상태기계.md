# 상태기계 문서

# SCS 상태기계 문서 (MVP) — Host 송출 + Viewer 시청(1:N), Host 모니터링은 “별도 디바이스 Viewer 접속 권장”

## 0. 목적과 범위

SCS(Signaling & Control Server)는 다음을 책임진다.

- 인증/인가
    - **Host: 로그인 필수(토큰 기반)**
    - **Viewer: 비로그인 허용(익명 세션 토큰 기반)**
- 룸 생성/입장/퇴장 및 권한 관리(Host-only start/end)
- WebRTC 시그널링(SDP/ICE) 라우팅(클라이언트 ↔ Media Gateway(SFU))
- On-Air(LIVE), 참여자 수, 연결 상태 등 룸 상태 관리
- Media Gateway(SFU)/AI Worker 트리거(세션 시작/종료)

**운영 정책(MVP)**

- Host가 변조 결과를 모니터링하려면 **별도 디바이스(모바일/태블릿/다른 PC)로 Viewer 접속을 권장**한다.
    
    (동일 PC에서 원본 소스와 변조 스트림 동시 재생 시 이중 재생/지연으로 음질 저하가 발생할 수 있음)

## 1. 역할(Role) 및 식별자(Identity)

### 1.1 Role

- **HOST (Publisher)**: Screen Capture로 원본 A/V를 SFU로 업로드
- **VIEWER (Audience)**: 변조된 결과 스트림을 SFU로부터 수신

### 1.2 Identity

- **HOST**: 로그인 기반 사용자 식별(`userId`, JWT 등)
- **VIEWER**: 비로그인 허용
    - SCS는 Viewer 접속 시 **Anonymous Viewer Token(AVT)** 발급/검증
    - Viewer 식별자는 `anonId`(또는 `viewerSessionId`)로 관리

---

## 2. Room 상태(State)

Room은 MVP에서 3단 상태로 운영한다.

| State | 의미 | Host | Viewer | 비고 |
| --- | --- | --- | --- | --- |
| `LOBBY` | 방송 시작 전(대기) | 0~1 | 0..N | 방 생성 직후 |
| `LIVE` | 방송 진행 중 | 1 | 0..N | On-Air |
| `ENDED` | 방송 종료 | 0 | 0 | 종단 상태 |

### Room 전이(Transition)

```
CREATE_ROOM -> LOBBY
LOBBY --(HOST_START + HOST_UPSTREAM_READY)--> LIVE
LIVE --(HOST_END)--> ENDED
LOBBY --(HOST_LEAVE/DISCONNECT)--> ENDED
LIVE --(HOST_DISCONNECT/TIMEOUT)--> ENDED

```

**MVP 정책(권장)**

- Host 이탈(정상/비정상) = Room 즉시 `ENDED`
- Viewer는 `LOBBY`/`LIVE` 모두 입장 가능(대기 화면/시청 화면)

---

## 3. Member(접속자) 연결 상태(State)

Room 내 각 접속자(Host/Viewer)는 SFU와의 협상/연결 상태를 갖는다.

| State | 의미 |
| --- | --- |
| `JOINED` | 룸 입장 완료(권한 체크 완료) |
| `NEGOTIATING` | SFU와 WebRTC 협상 중(offer/answer/ice 교환) |
| `CONNECTED` | SFU 연결 성립(송출/수신 가능) |
| `DISCONNECTED` | 소켓 종료/타임아웃/leave로 이탈 |

### Member 전이

```
JOINED -> NEGOTIATING -> CONNECTED
NEGOTIATING -> DISCONNECTED (timeout)
CONNECTED -> DISCONNECTED (leave/disconnect)
DISCONNECTED -> JOINED (재입장 허용 시)

```

## 4. 핵심 이벤트 및 규칙

### 4.1 Command (Client → SCS)

| Command | Sender | Preconditions | Effects |
| --- | --- | --- | --- |
| `room.create` | Host | Host 인증 성공 | Room 생성(`LOBBY`), Host member=`JOINED` |
| `room.join` | Viewer/Host | Room != `ENDED` | member=`JOINED` (Viewer는 AVT 발급/검증) |
| `room.leave` | all | member in room | member=`DISCONNECTED`; Host leave면 Room=`ENDED` |
| `room.start` | Host only | Room=`LOBBY` | “시작 의도” 기록(아직 LIVE 전이 X) |
| `host.upstream_ready` | Host only | `room.start` 이후 | **Room을 `LIVE`로 전이 + START 트리거 발행** |
| `room.end` | Host only | Room=`LIVE` | Room=`ENDED` + STOP 트리거 발행 |
| `signal.offer` | Host/Viewer | room member | sender=`NEGOTIATING`, SFU 라우팅 |
| `signal.answer` | Host/Viewer | offer 선행 | sender=`NEGOTIATING`, SFU 라우팅 |
| `signal.ice` | Host/Viewer | room member | SFU 라우팅 |
| `peer.connected` | Host/Viewer | room member | sender=`CONNECTED` |
| `peer.disconnected`(옵션) | Host/Viewer | room member | sender=`DISCONNECTED` |

**시작 UX 반영**

- Host가 버튼 클릭 → `room.start`
- 캡처 소스 선택 후 실제 업로드 연결 완료 → `host.upstream_ready`
    
    (혹은 `peer.connected`로 대체 가능하나, 의미 분리를 위해 별도 이벤트 권장)
    

### 4.2 Event (SCS → Client)

| Event | 대상 | 목적 |
| --- | --- | --- |
| `room.state.changed` | room topic | `LOBBY/LIVE/ENDED` 브로드캐스트 |
| `room.members.updated` | room topic | viewer 수/연결 상태 변경(필요 최소) |
| `signal.offer/answer/ice` | 특정 client | SFU 협상 메시지 전달 |
| `error` | 요청자 | 권한/상태 불일치/레이트리밋/room not found |

## 5. Media/AI 트리거 규칙 (세션 시작/종료)

### 5.1 START 트리거

- 발화 시점: **Room이 `LOBBY -> LIVE`로 전이될 때 1회**
- 조건:
    - Host `room.start` 수행
    - Host `host.upstream_ready` 수신(= 캡처 소스 선택 + 업로드 준비 완료)
- 동작:
    - SCS → Media Gateway/AI Worker: `session.start(roomId, hostId, transformConfig…)`

### 5.2 STOP 트리거

- 발화 시점: **Room이 `ENDED`로 전이될 때 1회**
- 조건:
    - Host `room.end` 또는 Host disconnect/timeout
- 동작:
    - SCS → Media Gateway/AI Worker: `session.stop(roomId, reason)`
    - Redis 상태 정리

---

## 6. 타이머/TTL(운영 안정성)

- **Upstream Ready Timeout**: `room.start` 후 N초(예: 30s) 내 `host.upstream_ready` 미수신 시
    - Room은 `LOBBY` 유지, Host에게 `error.upstream_timeout`
- **Negotiation Timeout**: `NEGOTIATING` 진입 후 N초 내 `peer.connected` 미수신 시 DISCONNECTED
- **Heartbeat/Presence TTL**: M초 이상 heartbeat 미수신 시 DISCONNECTED
- **AVT TTL + Rate limit**: 비로그인 viewer 폭주 방어(IP/룸 기준)

---

## 7. 불변조건(Invariants)

- Room당 Host는 최대 1명
- Room=`LIVE`는 Host 업스트림 준비 완료 이후만 가능
- Room=`ENDED`는 종단 상태
- 시그널링 메시지는 room member만 송신 가능
- Viewer는 익명(`anonId`) 기반이며 권한은 Viewer 범위로 제한

---

## 8. 예외 시나리오(최소)

- Host가 `room.start` 후 업스트림 연결 실패:
    - 타임아웃 후 `LOBBY` 유지 + 에러 반환
- Viewer가 `LOBBY`에 입장:
    - 허용(대기 UI), Room이 LIVE 전환되면 시청 협상 시작
- Host 모니터링:
    - **별도 디바이스 Viewer 접속 권장**(정책), SCS는 일반 Viewer와 동일 처리
